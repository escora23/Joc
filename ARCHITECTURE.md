# FRONT ULTRA: Architecture & Contracts

This document is the contract every agent builds against. `PROMPT.md` is the north star for **what** we
build and the quality bar. This file defines **how the pieces fit**. The source of truth for every type
lives in `src/shared/*.ts`. When this document and the code disagree, the code in `src/shared` wins and
this document gets fixed.

**Status:** every subsystem currently has a working **stub** written by the architect. It is minimal but real:
the app boots through loading → menu → setup → spawn → playing → command → ended, and every `?shot=` stages.
Each owner **replaces the internals of their stub** and keeps the exported factory and interface.

---

## 0. Golden rules

1. **Edit only files you own** (§1). If a blocking compile error is in someone else's file, make the smallest
   possible fix and mention it in your result. Never refactor another owner's code.
2. **Talk through contracts, not internals.** Consumers use only what `src/shared/` declares: the `GameContext`
   subsystem APIs, the `EventBus` events, `GameView`, the protocol, and pure helpers. You may *import and call*
   another owner's exported pure helpers (e.g. `sampleElevation` from `src/data`), but you may not depend
   on their private modules.
3. **`src/shared` is frozen-compatible.** It is owned by the architect. Any later change must be additive
   (new optional fields, new events, new helpers) and must not rename or remove anything. Exceptions are
   listed in §2.
4. **The simulation is deterministic** and lives in the Web Worker. Use only `game.rng` (or its `fork()`s) in
   the sim. Never use `Math.random()` or `Date` there. Rendering may be non-deterministic, but shots must not be.
5. **No network at runtime, no external art.** The only image files are the NASA textures in
   `public/textures`. Every other mesh, texture, sound and font is generated by code or bundled from npm
   (`@fontsource/*` is fine). No CDN.
6. **Shaders compile during loading.** Create all materials in `init()` and support `warmup(on)` (§5.4). Never
   create a new material type mid-game.
7. **No per-frame allocations in hot paths.** Reuse vectors and typed arrays, and use instancing. Do not rebuild
   geometry every frame. Upload textures by dirty region.
8. **`npx tsc --noEmit` must be clean and `npm run build` must pass** before you finish. Keep `strict` mode happy.
9. **Look at your work.** Stage your shots, capture them with `tools/capture.mjs`, open the PNGs and judge them
   honestly against the references in PROMPT.md. A critic will.

## 3. Subsystems & lifecycle

Every subsystem is created by `src/app/bootstrap.ts` with a factory `createX(ctx: GameContext)` exported from
its `index.ts`, and implements one interface from `src/shared/api.ts`:

| Factory (file) | Interface | Owner |
|----------------|-----------|-------|
| `loadWorldData(progress)`, `sampleElevation(world, lat, lon)`, `worldInit(world)` (`src/data/index.ts`) | module functions | data |
| `createSimClient(bus)` (`src/sim/client.ts`) + worker `src/sim/worker.ts` + `class Game implements SimGame` | `SimClientApi`, `GameView` | sim-core |
| `createAiDirector(game)` (`src/sim/ai/index.ts`), `createWorldEventDirector(game)` (`src/sim/events/index.ts`) | `AiDirector`, `WorldEventDirector` | sim-ai |
| `createCameraRig(ctx)` (`src/render/camera`) | `CameraRigApi` | globe |
| `createGlobe(ctx)` (`src/render/globe`) | `GlobeApi` | globe |
| `createPostPipeline(ctx)` (`src/render/post`) | `PostApi` | globe |
| `createUnitsRenderer(ctx)` (`src/render/units`) | `UnitsApi` | units |
| `createFx(ctx)` (`src/render/fx`) | `FxApi` | units |
| `createBattleRenderer(ctx)` (`src/render/battle`) | `BattleApi` | battle |
| `createCommandMode(ctx)` (`src/command`) | `CommandApi` | command |
| `createUi(ctx)` (`src/ui`) | `UiApi` | ui |
| `createAudio(ctx)` (`src/audio`) | `AudioApi` | audio |

`GameContext` (`ctx`) gives every subsystem: `renderer`, `canvas`, `scene` (strategic world scene), `camera`
(strategic camera), `bus`, `settings`, `quality`, `uiRoot`, `world`, `frame`, and **all other subsystems**
(`ctx.app`, `ctx.sim`, `ctx.globe`, `ctx.cameraRig`, `ctx.post`, `ctx.units`, `ctx.fx`, `ctx.battle`, `ctx.command`,
`ctx.ui`, `ctx.audio`).

**Lifecycle (`Subsystem`):**

| Method | When | Rules |
|--------|------|-------|
| factory | boot, in the order sim, camera, post, globe, units, fx, battle, command, audio, ui | Build scene-graph roots and subscribe to bus events. **Do not call other subsystems yet.** Add your root `Group` to `ctx.scene` here. |
| `init(progress)` | loading screen, all in parallel with data loading | Load and generate everything. Create **all** materials. Report 0..1. `ctx.world` may still be `null` (it arrives with data). Do not assume another subsystem finished `init`. |
| `warmup(on)` | after all inits, around `renderer.compileAsync` | Make every lazily-visible object visible (frustumCulled=false) so its program compiles, then restore it. |
| `onGameStart()` | a session started (`ctx.sim.view.config/world` set, first update applied) | Build per-game objects. |
| `update(frame)` | every frame (see §5 for order) | Cheap and allocation-free. |
| `onGameEnd()` | session torn down (return to menu or new game) | Remove every per-game object and reset state. |
| `resize(w, h, dpr)`, `setQuality(q)` | window resize, quality change | |

## 4. App state machine (owner: app)

```
boot ──► loading ──► menu ◄──────────────────────────────┐
                      │  ▲                                │
          ui: Play    ▼  │ ui: Back                       │ ui: returnToMenu()
                     setup                                │
                      │ ui: app.startGame(config)         │
                      ▼                                   │
                    spawn ──(sim phaseChanged→'playing')─► playing ◄──► command
                                                          │   ui: app.enterCommandMode(unitId)
                                                          │   command: bus 'commandExitRequested' → app.exitCommandMode()
                           sim 'gameOver' ────────────────┴──► ended ──► menu
```

| Transition | Driven by |
|------------|-----------|
| boot → loading | app (immediately after `ui.init` + `ui.showLoading()`) |
| loading → menu | app, after all `init`s + shader compile, and `loading.complete(requireInput=!isShot)` (the "press any key" gesture also unlocks audio) |
| menu ↔ setup | UI calls `ctx.app.goto('setup' / 'menu')` |
| setup → spawn | UI calls `ctx.app.startGame(ctx.app.makeConfig(...))`. App starts the sim, calls `onGameStart()` everywhere, emits `gameStarted`, and switches to `spawn` (or straight to `playing` if the sim already is). |
| spawn → playing | the sim's `phaseChanged {phase:'playing'}` event (after the human spawned; auto-spawn on timeout) |
| playing → command | UI (TAKE CONTROL button / `T` key) calls `ctx.app.enterCommandMode(unitId)`. App: camera dive (`flyTo` 3 km, tilted), `post.fadeTo(1)`, `sim.send(unitControl)`, `command.enter(params)`, state `command`, `commandEnter` event, `post.fadeTo(0)`. |
| command → playing | command emits `commandExitRequested` (Esc or unit killed) and app calls `exitCommandMode()`: fade, `command.exit()` → `CommandResult` → `sim.send(commandResult)`, state `playing`, `commandExit` event, fade in, climb `flyTo` 2500 km. |
| * → ended | the sim's `gameOver` event. App emits `gameEnded` and switches to `ended` (exiting command mode first). |
| * → menu | `ctx.app.returnToMenu()`: stop the sim, call `onGameEnd()` everywhere, emit `gameTornDown`. |

Pause and speed are not states: `ctx.app.setSpeed(0|1|2|4)` and `ctx.app.togglePause()` (→ `sim.setSpeed`, bus
`speedChanged`). UI reads `ctx.sim.view.speed`.

On every transition the app calls `ui.setState(next, prev)` and emits `appState {state, prev}`. The app also sets
the camera mode (`menu` auto-rotate / `game` / `cinematic`), the globe territory opacity (0 on menu, 1 in
game), the audio mood, and enables the input router only in `spawn` / `playing`.

## 5. Rendering

### 5.1 One renderer, two scenes
* **One `THREE.WebGLRenderer`** created by app (`antialias:false`, `stencil:false`, `powerPreference:'high-performance'`),
  pixel ratio `min(devicePixelRatio, quality.pixelRatioCap)`.
* **Strategic scene** `ctx.scene` with camera `ctx.camera` (= `ctx.cameraRig.camera`). Globe, units, fx and battle
  each add **one root `Group`** to it.
* **Command scene** `ctx.command.scene` / `ctx.command.camera`: its own world in meters (1 unit = 1 m), same renderer.
* **`ctx.post.render(scene, camera, frame)` is the only path to the canvas.** Nobody else calls `renderer.render` on
  the default framebuffer. (Render-to-texture for your own effects is fine, e.g. an offscreen cloud pass.)

### 5.2 Frame loop (app, `renderer.setAnimationLoop`)
```
frame.now/dt/time/frame                      (dt clamped to 0.1 s)
ctx.sim.pump(now)                            → applies buffered worker updates, emits tilesChanged / sim events / simTick
frame.simAlpha/simTime/simDt/worldTime
input.update()                               → worldHover (once per frame, only if pointer/camera moved)
if state === 'command':
    command.update → audio.update → ui.update → post.update → post.render(command.scene, command.camera)
else:
    cameraRig.update → globe.update → units.update → fx.update → battle.update
    → audio.update → ui.update → post.update → post.render(ctx.scene, ctx.camera)
```
While in command mode the strategic subsystems (camera, globe, units, fx, battle) are **not updated**. They must
tolerate the gap and re-sync from `ctx.sim.view` on the next `update`. Bus events still reach them, so accumulate
dirty state in handlers and do the work in `update`.

### 5.3 Render order in the strategic scene (`renderOrder`)
| renderOrder | What | Owner |
|-------------|------|-------|
| -100 | stars / Milky Way sky (camera-centred, `depthWrite:false`) | globe |
| 0 | earth surface (opaque, relief) | globe |
| 5 | territory overlay (if separate from the surface shader), borders, front glow | globe |
| 10 | battle terrain patches, craters (opaque) | battle |
| 20 | structures, units, instanced soldiers/vehicles (opaque) | units / battle |
| 30 | clouds (+ cloud shadows are in the surface shader) | globe |
| 40 | atmosphere (additive / back-face shell) | globe |
| 50 | fx: fireballs, smoke, trails, tracers, shockwaves (transparent, `depthWrite:false`) | units(fx) / battle |
| 60 | nation labels, selection rings, previews (on top, depth-tested against the globe) | globe / units |

### 5.4 Color, HDR & shaders
* `renderer.outputColorSpace = SRGBColorSpace`. Color textures use `SRGBColorSpace`. Data textures (topology, water,
  owners, masks) use `NoColorSpace`.
* Post (globe owner) renders the scene into **HalfFloat HDR targets** and applies tone mapping (ACES Filmic) and
  output conversion at the end. So materials output **linear HDR**. Emissive things (city lights, fireballs,
  tracers, borders) may exceed 1.0 to drive bloom.
* **Custom `ShaderMaterial`s must end their fragment shader with**
  `#include <tonemapping_fragment>` and `#include <colorspace_fragment>`. Three.js turns these into no-ops when
  rendering into the post pipeline's targets, so the shader is correct in both pipelines.
* Grid-ordered data textures (row 0 = north, as in `WorldData`) are uploaded with `flipY=false`. Sample them with
  `v = 1.0 - uv.y` on the sphere.
* **Warm-up:** after every `init`, app calls `warmup(true)` on all subsystems, then `renderer.compileAsync(ctx.scene,
  ctx.camera)` and `compileAsync(command.scene, command.camera)`, then `warmup(false)`. Anything that can appear later
  (nuke fireball, every unit type, battle soldiers, command-mode enemies and effects) must be in the scene graph
  at that moment with its final material.

### 5.5 Precision & camera ranges
* Globe radius 1.0 = 6371 km, so 1 m ≈ 1.57e-7 units. Keep ground-level meshes **local**: parent them to a `Group`
  positioned at the site (e.g. a battle patch anchored at a front) so vertex coordinates stay small. Three.js
  composes `modelViewMatrix` in double precision on the CPU.
* The camera rig sets `near/far` dynamically from altitude (near ≈ 2% of the distance to the target, far covers
  the horizon plus the planet). Draw the sky with `depthTest/depthWrite` off so it is never clipped. No
  logarithmic depth buffer.
* Altitude range `CAMERA_MIN_ALT_KM` (0.35 km) to `CAMERA_MAX_ALT_KM` (42,000 km). The camera tilts toward the horizon as it
  descends. `BATTLE_LAYER_ALT_KM` (600 km) is where the battle layer starts fading in.
* The camera never rotates the globe. **The planet is fixed in world space; the sun moves** (§7).

## 6. Coordinates (`src/shared/geo.ts`)

* **Tile grid:** `MAP_W × MAP_H = 1600 × 800` equirectangular, 0.225° per tile (~25 km at the equator).
  Tile `(x, y)`: `x = 0` at lon −180, `y = 0` at lat +90. `tile = y * 1600 + x`. **x wraps**, y clamps.
  Continuous tile coordinates `(fx, fy)`: `lon = fx/1600*360 − 180`, `lat = 90 − fy/800*180`. The **center** of tile `(x, y)`
  is `(x + 0.5, y + 0.5)`. Units, fronts, labels and scars in the protocol use continuous tile coordinates.
* **Sphere (Three.js Y-up, radius 1 = Earth radius):**
  `x = cos(lat)·cos(lon)`, `y = sin(lat)`, `z = −cos(lat)·sin(lon)`. So lon 0 → +X, 90°E → −Z, 90°W → +Z,
  north pole → +Y. **This matches an unrotated `THREE.SphereGeometry` (default phi/theta) textured with the
  equirectangular NASA maps** (verified numerically, max error 2e-7). Use `latLonToVec3`, `vec3ToLatLon`,
  `tileToVec3`, and `tangentFrame(lat, lon, east, north, up)`.
* **Heading** (units, camera): radians, 0 = north (−y in tile space), π/2 = east (+x).
* **Relief:** `topoToMeters(gray) = gray/255 × 8848 m` (linear). The ground radius is
  `surfaceRadius(elevationMeters) = 1 + max(0, e)·RELIEF_EXAGGERATION / 6,371,000`. Globe displacement,
  battle terrain and unit placement **all** use this (or `ctx.globe.surfaceRadiusAt(lat, lon)`, which is
  `surfaceRadius(sampleElevation(world, lat, lon))`), so everything sits on the same surface. Water is at radius 1.0.
* **Terrain byte** (`WorldData.terrain`): the low 4 bits are `TerrainClass` (Ocean, Lake, Plains, Hills, Mountains, Ice)
  and the flags are `Shore 0x10`, `Navigable 0x20`, and `River 0x40`. Land south of −60° (`ICE_LATITUDE`) is **Ice**: not
  ownable, not traversable, not counted in `landTiles`. The 80% win share counts ownable land tiles.

## 7. Time

* **Fixed sim tick 100 ms (10 Hz) at 1×.** Speeds are 0 (pause), 1, 2 or 4. The worker runs `speed` ticks per
  100 ms of wall time and posts **one coalesced `TickUpdate` per 100 ms** (0 ticks while paused, still posted
  every ~500 ms). During the spawn phase it runs 1 tick per interval.
* **Interpolation:** `GameView.alpha` (and `frame.simAlpha`) = time since the last applied update ÷ 100 ms, clamped
  to 0..1. Units carry `prevX/prevY/prevHeading/prevAlt` from the previous update: lerp with alpha.
  `frame.simTime` = interpolated game seconds. `frame.simDt` = game-time delta of the frame (0 when paused). Use it
  for anything that should freeze on pause (unit animation, fire, smoke). Use `frame.dt` for UI and camera.
* **World clock and sun:** `frame.worldTime` = `config.startWorldTimeSec + simTime` in a session, and a slow drift on the
  menu. `sunDirection(worldTime)` gives the world-space direction to the sun: the subsolar point circles
  westward once per `DAY_LENGTH_SEC` (720 game seconds) at latitude `SUBSOLAR_LAT_DEG` (12°N). All lighting (globe,
  units, battle, command mode) uses it so the terminator is consistent everywhere. `worldTimeForSubsolarLon(lon)`
  places noon over a longitude (shots). `DEFAULT_START_WORLD_TIME` puts noon at 20°E.

## 8. Simulation protocol (`src/shared/protocol.ts`)

The sim lives in a module Web Worker (`src/sim/worker.ts`). The main thread talks to it only through
`ctx.sim` (`SimClientApi`) and reads state only through `ctx.sim.view` (`GameView`).

**Main → worker (`ToWorker`):**
`init {config, world: WorldInit}` (WorldData minus `relief`, structured-cloned once), `command {playerId, cmd}`,
`speed`, `debug {action}`, `fastForward {ticks, requestId}`, `stop`.

**`PlayerCommand`** (the human via UI, the AI via `game.issue`, validated identically). Invalid commands produce a
`message` event with an i18n key.
`spawn`, `attack {target (0 = unclaimed land), ratio, tile}`, `retreat`, `boatAttack {targetTile, ratio}`,
`build {structure, tile}`, `upgrade`, `demolish`, `buildUnit {unit, structureId}`,
`launch {weapon: AtomBomb|HydrogenBomb|Mirv|CruiseMissile, targetTile, siloId}`, `moveUnit`,
`deployArmor {unitId, targetTile}`, `airStrike {unitId, targetTile}`, `allianceRequest`, `allianceReply`,
`breakAlliance`, `embargo`, `donate {gold, troops}`, `emote`, `targetPlayer`, `unitControl {unitId, controlled}`,
`commandResult {unitId, kind, enemy, tile, troopsKilled, unitsDestroyed[], structuresDestroyed[], unitLost}`.

**`SimDebugAction`** (shots and playtests only, applied immediately between ticks, also while paused):
`endGame`, `addGold`, `addTroops`, `conquer {playerId, centerTile, radius}`, `spawnStructure`, `spawnUnit`,
`launchNuke`, `worldEvent`. sim-core must keep implementing these: every shot stager depends on them.

**Worker → main (`FromWorker`):** `ready`, `update {u: TickUpdate}`, `fastForwardProgress`, `fastForwardDone`, `error`.

**`TickUpdate`** (every typed array is freshly allocated and **transferred**, see `tickUpdateTransferables`):

| Field | Type | When |
|-------|------|------|
| `tick`, `ticks`, `phase`, `speed` | numbers | always |
| `owners` | `Uint32Array` of `packTileOwner(tile, owner)` (tile 21 bits, owner 11 bits), in change order | always (may be empty) |
| `fullOwners` | `Uint16Array(TILE_COUNT)` | first update, after fast-forward, or when a delta would be huge |
| `players` | `Float64Array`, rows of `PLAYER_STRIDE` laid out by `PF` (id, alive, tiles, troops, maxTroops, troopGrowth, gold, income, population, attackingTroops, labelX/Y/Size, traitorTicks, spawned, capitalTile) | always, all players |
| `playerMeta` | `PlayerMeta[]` (name, kind, personality, color, countryIndex, allies, embargoes) | new or changed players only |
| `playerStats` | cumulative `PlayerStatsCounters` | every ~10 ticks |
| `units` | `Float32Array`, rows of `UNIT_STRIDE` laid out by `UF` (id, type, owner, x, y, heading, state, hp, troops, targetX/Y, alt, originX/Y) | always, all live units |
| `structures`, `attacks`, `fronts`, `scars`, `worldEvents`, `alliances`, `allianceRequests`, `doomsday`, `spawnDeadlineTick`, `winner` | lists and values | only when changed (the client keeps the last value) |
| `events` | `SimEvent[]` | always |

**Fronts** (`FrontRecord` → `FrontView`) are the battle layer's input: one per active attacker→defender contact,
with a representative point, `intensity` 0..1, troop numbers, length, advance direction and ≤ 64 polyline
samples along the contact line. sim-core computes them at least every 5 ticks.
**Labels:** sim-core computes a label anchor and size per player (largest interior area) at least every 10
ticks. The globe renders them.

**Client (sim-core, `src/sim/client.ts`):** buffers worker messages and applies them in `pump()` at frame start.
For each update it applies tiles, emits `tilesChanged`, updates players, units, structures and lists, records
`history` (every 50 ticks) and `timelapse` (400×200 RLE frames every 100 ticks), re-emits every `SimEvent` on the
bus under its `type`, emits `nukeAlarm` when a nuke targets the human, then emits `simTick`.

## 9. In-worker game API (`src/shared/simapi.ts`): sim-core ↔ sim-ai

`class Game implements SimGame` (sim-core). sim-ai receives the `SimGame` and must use **only** that interface.

* **Queries:** `ownerOf`, `isLand/isWater/isPlayable/isShore`, `borderTiles(pid)`, `neighborsOf(pid)`,
  `players()`, `player(id)`, `structures(owner?, type?)`, `units(owner?, type?)`, `unitsNear`, `structuresNear`,
  `outgoingAttacks`, `incomingAttacks`, `isAllied`, `hasEmbargo`, `structureCost`, `unitCost`, `canBuild`, `distance`.
* **AI actions:** `issue(playerId, PlayerCommand)` (exactly like the human) and `addPlayer(def)` for nations,
  tribes and rebels.
* **World-event mutations:** `transferTiles`, `destroyStructure`, `damageUnit`, `addGold`, `addTroops`,
  `setModifier(pid, 'troopGrowth'|'goldIncome'|'attackPower'|'defensePower'|'maxTroops', value, ticks)`,
  `setWorldEventState(id, state|null)` (renderable active events), `setDoomsday(level)`, `emit(event)`, `nextEventId()`.
* `SimPlayer.aiMemory` is a free slot for sim-ai's per-player state.
* **Tick order** (sim-core): 1. queued human commands, 2. `aiDirector.tick()`, 3. `worldEvents.tick()`,
  4. attacks and expansion, 5. units and projectiles, 6. economy, 7. alliances and timers, 8. win check, 9. deltas and events.
  `aiDirector.onEvent` and `worldEvents.onEvent` receive every emitted event synchronously.
* **Spawning:** the human is always **player 1** (`HUMAN_ID`). `aiDirector.setup()` runs in the `Game` constructor,
  creates the AI nations at real countries (named after them via `countryIndex`, using `WorldData.countries`
  capitals and weights) and tribes, and spawns them with `issue(id, {type:'spawn'})`.
* `GameConfig.humanAutopilot` (shots and playtests): the AI director also plays player 1.

## 10. Event bus (`src/shared/events.ts`)

`ctx.bus: EventBus<GameEvents>` has synchronous dispatch and typed payloads: `bus.on(name, fn) → unsubscribe`,
`once`, `emit`, and `wait(name, pred?) → Promise`. Payloads may be reused after dispatch, so copy what you keep.
`GameEvents = AppEvents & SimEventMap`.

**Sim events** (re-emitted by the sim client, payload = the `SimEvent`): `phaseChanged`, `playerSpawned`,
`attackStarted`, `attackEnded`, `boatLaunched`, `boatLanded`, `nationEliminated`, `capitalCaptured`,
`allianceRequested`, `allianceFormed`, `allianceRejected`, `allianceBroken` (traitor), `allianceExpired`,
`embargoChanged`, `donation`, `structureBuilt`, `structureUpgraded`, `structureDestroyed`,
`structureCaptured`, `unitSpawned`, `unitDestroyed`, `combat` (shells, SAM, artillery, bombs: visuals and audio),
`nukeLaunched`, `nukeIntercepted`, `nukeDetonated`, `worldEvent`, `doomsday`, `emote`, `tradeCompleted`,
`goldBonus`, `message`, `commandResultApplied`, `gameOver`.

**App events:**

| Event | Emitted by | Typical listeners |
|-------|-----------|-------------------|
| `appState {state, prev}` | app | everyone |
| `resize`, `settingsChanged`, `languageChanged`, `qualityChanged` | app | ui, renderers, audio |

## 11. Input & hotkeys

* The canvas receives pointer events. DOM UI sits above in `#ui` with `pointer-events:none`. Interactive panels set
  `pointer-events:auto` (class `fu-interactive`, or buttons/inputs), so clicks on empty screen reach the world.
* **Camera rig** (globe owner) owns: left-drag = pan/orbit, right- or middle-drag = heading/tilt, wheel = zoom
  (**ignored when Shift is held**), WASD/arrows = pan, Q/E = rotate, R/F = zoom, and `focusRequest` flights.
* **App input router** turns a press without drag (< 6 px, < 450 ms) into `worldClick`, and pointer moves into
  `worldHover`, with picking resolved (unit > structure > tile). The right-click context menu is suppressed.
* **UI** owns all gameplay semantics and keyboard shortcuts (ignore keys while an input has focus or when not in
  `playing`):

| Key | Action | Key | Action |
|-----|--------|-----|--------|
| Left click | expand into / attack the clicked owner (boat attack if across water) | Right click | diplomacy radial menu on the clicked nation |
| `1`…`0` | build City, Port, Factory, Defense Post, SAM, Silo, Airbase, Army Base, Naval Yard, Radar (`STRUCTURE_DEFS[].hotkey`) | Shift + wheel | attack ratio |
| `Z` / `X` / `C` / `V` | target Atom bomb / Hydrogen bomb / MIRV / Cruise missile | `T` | TAKE CONTROL of the selected tank/jet/ship |
| `B` | boat attack at hover | `Space` | pause / resume |
| `+` / `-` | speed up / down | `Tab` | leaderboard |
| `M` | minimap toggle | `H` / `Home` | fly to capital (`focusRequest`) |
| `Esc` | cancel mode / close panel / pause menu | `Enter` | quick-chat emotes |

* **Command mode** owns input while active (pointer lock, WASD, mouse aim, fire, `Esc` → `commandExitRequested`).
  Strategic hotkeys must check `ctx.app.state === 'playing'`.

## 12. Shot hooks (`?shot=<name>`)

`registerShot(name, owner, description, stage, settleFrames=30)` in each owner's `shots.ts`. `src/app/shots.ts`
imports them all. After loading (menu state, audio muted, no "press any key"), app runs the stager, waits
`settleFrames` frames, and sets `window.__shotReady = true`. Stagers get `{ctx, params, waitFrames, wait, setUiVisible}`.
`&hud=0` hides the DOM UI for any shot. `&lang=en` and `&quality=low|medium|high|ultra` override settings.

**Deterministic staging:** `ctx.app.startScriptedGame(opts)` starts a session with seed 1337, 24 AIs, the human at
Madrid, `instantStart`, `humanAutopilot`, a `headStart` disc of land, then `fastForward(ticks)`, and sets
`speed` (0 freezes). `worldTimeSec` is the lighting **at capture time**. Then place the camera with
`ctx.cameraRig.setState({lat, lon, altitudeKm, tilt, heading})`, and use `ctx.sim.debug(...)` to stage
units, structures, nukes or the end of the game.

| Shot | Stages | Owner |
|------|--------|-------|
| `loading` | cinematic loading screen frozen at ~62% | ui |
| `menu` | main menu over the slowly rotating Earth | ui |
| `setup` | skirmish setup screen | ui |
| `spawn` | spawn phase: AI nations placed, "click to found your capital", Europe | ui |
| `orbit` | photoreal Earth from orbit, daylight, no UI | globe |
| `night` | night side: city lights and terminator over Europe | globe |
| `territory` | tick 3000: nation colors, glowing borders, labels, Europe, no UI | globe |
| `midgame` | tick 3000: typical play view with full HUD | app |
| `hud` | HUD close-up with panels open (selection, leaderboard, ticker, toasts) | ui |
| `front` | ground level (~2.5 km, tilted) over the hottest front: infantry, tanks, artillery, explosions | battle |
| `front-wide` | ~250 km over an active front: hot front line, battle layer fading in | battle |
| `units` | ships with wakes, jets with contrails, missiles, Mediterranean | units |
| `nuke` | hydrogen bomb on Paris at fireball and mushroom time (`&after=N` frames) | units |
| `structures` | every structure type on Spain, close orbit | units |
| `command-tank` / `command-jet` / `command-ship` | inside command mode for each vehicle | command |
| `end` | victory screen: stats, territory graph, timelapse | ui |
| `data-debug` | 2D map of terrain classes, shores, country raster | data |

Owners may add more shots (e.g. `radial`, `settings`, `tutorial`, `hurricane`, `doomsday`, `ground-dive`) in their
own `shots.ts`. Capture with:
```
npx vite --host 127.0.0.1 --port <yourPort> --strictPort   # background
node tools/capture.mjs --url http://127.0.0.1:<yourPort>/ --shot front,front-wide --out shots/<you> --wait 8000
```
`tools/playtest.mjs --url ... --seconds 30` drives a real click-through (menu → setup → spawn click → attacks).
Headless Chromium uses SwiftShader (no GPU), so **fps numbers there mean nothing**. Judge performance by design.

## 13. Quality presets & performance budgets

`ctx.quality: QualityProfile` (`src/shared/quality.ts`). The default is **High**. Subsystems read it in `init()` and
re-apply it in `setQuality(q)`.

| Field | Low | Medium | High | Ultra | Used by |
|-------|-----|--------|------|-------|---------|
| pixelRatioCap | 0.85 | 1 | 1.5 | 2 | app |
| antialias | none | FXAA | SMAA | MSAA×4 | post |
| bloom | off | half-res | full | full | post |
| cinematicPost (vignette, grain, CA, dirt, haze) | – | – | ✓ | ✓ | post |
| globeDetail (mesh/relief LOD) | 0 | 1 | 2 | 3 | globe |
| textureSize | 2048 | 4096 | 4096 | 4096 | globe |
| clouds (static / animated / + shadows) | 0 | 1 | 2 | 2 | globe |
| atmosphere (rim / single / multi-sample) | 0 | 1 | 2 | 2 | globe |
| ocean (flat / normals+glint / +foam) | 0 | 1 | 2 | 2 | globe |
| particles | 2k | 6k | 15k | 30k | fx, battle, command |
| battleInfantry / battleVehicles | 1.5k / 80 | 5k / 200 | 12k / 400 | 25k / 800 | battle |
| decals | 32 | 96 | 192 | 384 | battle, fx |
| shadows (command mode) | off | 1024 | 2048 | 4096 | command |
| commandViewDistance / commandDetail | 1.5 km / .25 | 3 km / .5 | 5 km / .8 | 8 km / 1 | command |
| maxVoices | 16 | 24 | 32 | 48 | audio |

**Per-frame budgets (High, mid-range laptop GPU, 60 fps = 16.6 ms):**

| Budget | Strategic view | Command mode |
|--------|---------------|--------------|
| Draw calls | ≤ 250 (globe ≤ 40, units ≤ 60, fx ≤ 40, battle ≤ 80, labels ≤ 20) | ≤ 400 |
| Triangles | ≤ 1.5 M | ≤ 2.5 M |
| Main-thread JS | ≤ 6 ms total (sim client pump ≤ 1 ms, UI DOM ≤ 1.5 ms, each renderer ≤ 1 ms) | ≤ 6 ms |
| Texture upload | ≤ 1 MB per frame after loading (dirty rectangles for territory) | – |
| GC | no per-frame allocations in update loops | same |
| Sim worker | ≤ 25 ms per tick at 1× with 64 AI nations and tribes (4× must keep up) | – |

DOM: update HUD text at most every ~100 ms. Use `transform`/`opacity` for animation. Never read layout in
loops. Leaderboard and minimap refresh at ≤ 4 Hz.

## 14. i18n & settings

* **Spanish is the default.** English is a toggle (menu and settings). `t(key, params)` and `tn(key, count)`. Missing keys
  fall back to es → en → the key itself (logged once).
* The ui owner owns `src/ui/i18n/es.ts` and `en.ts` (registered in `createUi`). **Other owners register their own
  namespaced keys** from their directory (`registerDictionary('es', {'command.hud.ammo': 'Munición'})`), in both
  languages. Prefix keys with your area: `command.*`, `battle.*`, `audio.*`, `data.*`, `news.*` (ui), `msg.*` (sim
  message keys: sim-core picks keys and ui provides the texts).
* Nation names: `playerName(player, world)` localises AI nations through `WorldData.countries[i].nameEs/nameEn`.
  The data owner provides good Spanish names.
* Number formatting: `formatNumber`, `formatCompact` (12,4K / 3,2M in es), `formatDuration`.
* **Settings** (`ctx.settings`): language, quality, volumes (master/music/sfx/ui), mouse sensitivity, invertY, edgePan,
  showFps, tutorial, screenShake, last setup. They persist to `localStorage['frontultra.settings.v1']` with every
  access in try/catch. Changes go through `settings.set(patch)`. App reacts (language → `setLanguage` +
  `languageChanged`, quality → `qualityChanged` + `setQuality`) and emits `settingsChanged`.

## 15. Command mode contract (command, app)

* **Eligible units:** `UNIT_DEFS[type].command`: ArmoredDivision → `tank`, FighterSquadron → `jet`, Warship → `ship`.
* **Enter** (`CommandEnterParams`): unit id and type, kind, lat/lon/tile, owner, the **enemy** (app picks the
  dominant non-allied foreign owner within 40 tiles), both nations' colors and troop counts, a deterministic `seed`,
  `worldTimeSec` (sun), and difficulty. Build the battlefield from real elevation (`sampleElevation`) and
  `WorldData.terrain` at that place (coast, water, mountains), enemies in the enemy's color, and your own HUD
  (`src/command/hud*`, may use the CSS variables from `src/ui/styles.css`).
* **Exit** (`CommandResult`): `troopsKilled` in **strategic troops** (the command owner defines the conversion,
  e.g. 1 enemy tank ≈ 800 troops, 1 soldier ≈ 25, scaled by difficulty), destroyed strategic unit ids,
  `unitLost`. The sim applies them (`commandResult`) and emits `commandResultApplied`. If the player dies, emit
  `commandExitRequested {reason:'killed'}` and return `unitLost: true`.
* The sim keeps running while you fight (`unitControl` freezes the controlled unit in the sim).
* Pointer lock, cursor and key listeners are acquired in `enter()` and released in `exit()`.

## 16. Data pipeline expectations (data)

`loadWorldData(progress)` returns `WorldData` in a few seconds (a worker or build-time bake is fine; any baked file
must be generated from the NASA and Natural Earth sources by a script in `tools/` or `src/data/`, and committed only if
small):
* `terrain` from the 1600×800 water mask (white = water). Thin rivers (1–2 px) become land with the `River` flag. Small
  enclosed water becomes `Lake`, ocean-connected water gets `Navigable`, and shores are flagged. Elevation classes come
  from `earth-topology.png` (Hills ≥ 600 m, Mountains ≥ 1800 m, tunable). Ice below −60°.
* `country` rasterised from `world-atlas/countries-50m.json` onto the grid with exact indices (no antialias blending),
  with every playable land tile assigned to its nearest country.
* `countries`: ISO codes, **English and Spanish names**, capital lat/lon (a hand-curated table for real capitals),
  tile counts, and a `weight` for AI selection.
* `relief` at ≥ 2048×1024 meters. `sampleElevation(world, lat, lon)` is bilinear.
* The `data-debug` shot must make any error obvious.

## 17. Audio contract (audio)

All sound is procedural Web Audio. `ctx.audio.unlock()` is called by app on the first user gesture (and never in shot
mode). The engine listens to the bus (UI sounds, combat, nukes, alarms, world events, state changes) and exposes
`play`, `playAt(cue, lat, lon)` (attenuated by camera distance via `cameraMoved`), `setMood(MusicMood)` (adaptive
music: menu, calm, tension, war, nuclear, command, victory, defeat, silence) and `duck(level, holdMs, releaseMs)`
(the nuke silence-then-roar). Volumes come from settings (master, music, sfx, ui). Keep the voice count ≤ `quality.maxVoices`.

## 18. UI layering (ui)

* `#app` holds the `<canvas>` (z 0) and `#ui` (z 10, `pointer-events:none`). The command HUD goes in its own
  container under `#ui` (z 20). The loading screen is z 100. Fades and flashes are done in WebGL by post, not the DOM.
* Fonts must be bundled (`@fontsource/*`). Numbers use a monospace or tabular font. Icons are inline SVG.
* UI never mutates sim state directly: `ctx.sim.send(cmd)`, `ctx.app.*`, bus events.
